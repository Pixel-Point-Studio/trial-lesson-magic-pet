# Короткая теория для преподавателя

## Модель урока

Ученик проходит настоящий цикл разработки: наблюдает дефект, формулирует ожидаемое поведение, находит обработчик входа, проверяет значение breakpoint-ом, меняет одну строку и повторяет тот же тест.

## Пять понятий бытовым языком

- Ввод — сообщение или callback кнопки, который пришёл программе.
- Условие — выбор следующего действия на основе фактического значения.
- Метод — названное действие продукта, например выбрать сценарий или удалить задачу.
- Состояние — память о том, на каком шаге находится пользователь.
- Контракт — заранее согласованная форма взаимодействия с Telegram, SQLite или AI.

## Контрольные вопросы

1. Какое значение реально пришло в `buttonId`?
2. Какое условие программа проверяет?
3. Какой метод вызывается, если условие истинно?
4. Что сохранится после перезапуска?
5. Чем удаление отличается от выполнения задачи?
6. Почему подпись кнопки можно менять, не меняя callback ID?

Не объяснять Telegram SDK, JDBC, HTTP или JSON, пока это не нужно для ответа ученика. Главный файл ученика — `StudyLesson.java`, `SportLesson.java` или `BlogLesson.java`; `StudentBot` только передаёт события выбранному маршруту, а инфраструктура уже проверена тестами.
