**Пробный урок Magic Pet** — индивидуальная встреча на 90 минут для лида 13–25 лет. Лид впервые работает как разработчик: приходит в существующий проект, читает README, создаёт личную Git-ветку, настраивает окружение, запускает продукт, находит контролируемую проблему, исправляет её и видит результат в Telegram.

Главный результат: **«Я разобрался в существующем проекте, изменил код — и настоящий бот на моём телефоне заработал иначе».**

Magic Pet — Telegram-бот, в котором пользователь выбирает путь «Учёба», «Спорт» или «Личный блог», даёт питомцу имя и цель, получает план, выполняет задания, зарабатывает XP и видит эволюцию Руни, Игниса или Скрибы.

## Для кого этот документ

Главная методичка МОПа. Открыть перед уроком и держать рядом во время встречи. Теория, технический справочник и ответы на задания вынесены в отдельные дочерние документы.

## Цели

К концу практики лид:

- понимает, что разработчик обычно развивает существующий проект;
- знает роль README, репозитория, issue и отдельной ветки;
- понимает цепочку **ввод → условие → метод → результат**;
- использовал breakpoint и сделал один шаг отладки;
- внёс минимум одно логическое и одно творческое изменение;
- прошёл выбранный сценарий и увидел эволюцию Magic Pet;
- предложил следующую функцию.

Не цель: объяснить всю Java, Git, Telegram API, SQL или AI.

## Роли

**Лид делает руками:** вводит команды, читает README, меняет .env, запускает проект, ставит breakpoint, правит код и проверяет Telegram.

**МОП направляет:** задаёт вопросы, выдаёт подсказки ступенями, следит за временем и не забирает клавиатуру, кроме аварийного восстановления.

## Принцип занятия

> Наблюдаем поведение → формулируем гипотезу → находим место в коде → делаем минимальное изменение → повторяем тот же тест.
> 

Перед каждым запуском спрашивать: **«Что, по-твоему, изменится сейчас?»**

# Полный сценарий МОПа

## 0–5. Контакт

Сказать: **«Сегодня не будет длинной лекции. Ты попробуешь работу разработчика на настоящем проекте и изменишь Telegram-бота».**

Спросить об опыте, интересе и наличии Telegram. Если опыта нет — нормализовать. Если есть — давать больше самостоятельности.

## 5–9. Демо

За 90 секунд показать: /start → путь → имя → цель → задание → XP → эволюция. Код решения не показывать.

Сказать: **«Сегодня ты не просто воспользуешься ботом — ты войдёшь в проект как разработчик».**

## 9–14. README

Попросить найти README и ответить: что делает проект, что нужно для запуска, какая команда запуска и где учебный файл.

Объяснить: разработчик начинает с карты проекта и задачи, а не читает каждый файл.

## 14–20. Git

Выполнить:

- git status
- git branch --show-current
- git switch -c lesson/имя-фамилия

Сказать: **«Репозиторий — история проекта. Ветка — твоя безопасная версия этой истории».**

Не выполнять git init: проект уже является репозиторием.

## 20–28. Telegram и .env

Если личный бот создаётся за пять минут — использовать его. Иначе перейти на отдельный школьный бот.

Показать .env.example, создать .env и заменить только TELEGRAM_BOT_TOKEN.

Сказать: **«Код можно показывать команде, токены — нет. Поэтому секреты лежат в локальном файле, который Git не сохраняет».**

## 28–34. Первый запуск

Запустить ./gradlew run, открыть чат и отправить /start.

Спросить: **«Что сейчас было вводом? Какой результат вернула программа?»**

Пустой LLM_API_URL и fallback — штатный режим.

## 34–41. Выбор issue

Выбрать один путь:

- Руни: вместо Study выбирается Sport;
- Игнис: кнопка Sport не срабатывает из-за несовпадения ID;
- Скриба: удаление вызывает неверный метод.

Сначала воспроизвести и сформулировать «ожидали / получили».

## 41–54. Breakpoint

Открыть StudentBot.receiveMessage(). Поставить breakpoint в обработчике кнопки. Повторить действие.

Найти buttonId, user.state(), Scenario и следующий метод.

Сказать: **«Breakpoint — пауза: мы не гадаем, а видим реальные данные».**

## 54–62. Исправление

Лид меняет одну строку: значение, условие или метод. До запуска делает прогноз. После перезапуска повторяет тот же тест.

Если не получилось — идти по лестнице подсказок.

## 62–69. Творческое изменение

Предложить выбор:

- подпись кнопки в ui-texts.ru.json;
- сообщение эволюции;
- одно fallback-задание;
- правило prompt, если AI подключён.

Результат должен быть виден в Telegram за три минуты.

## 69–73. Вау-финал

Дойти до 100 XP и уровня 2. Лид сам нажимает кнопки и объясняет, почему Pet изменился. Третий уровень — только идея продолжения.

## 73–77. Сохранение

Выполнить git diff, git status, добавить только изменённые учебные файлы и сделать commit. Не добавлять .env, базу или токены.

## 77–80. Рефлексия

Спросить:

- где программа получила ввод;
- какое условие выбрало действие;
- какой метод был вызван;
- как breakpoint помог найти причину;
- что добавить следующим.

## 80–90. Мост к курсу

Сказать: **«Сегодня ты прошёл короткую версию реальной разработки: получил проект, прочитал документацию, создал ветку, настроил окружение, нашёл ошибку, изменил код и сохранил результат».**

Связать курс с опытом: Java — условия и методы; ООП — структура проекта; базы — сохранение; Git — команда; Telegram/API — продукт; AI — внешний сервис с контрактом и fallback.

# Лестница подсказок

1. «Что ожидали и что получили?»
2. «Где обрабатывается эта кнопка?»
3. «Сравни идентификатор в двух местах».
4. «Проблема в тексте, условии или методе?»
5. Показать нужные 3–5 строк.
6. Дать точную замену и попросить объяснить.

Не держать в тупике дольше трёх минут.

# Критерии успеха

- бот ответил;
- создана ветка;
- лид воспроизвёл и исправил дефект;
- использовал breakpoint;
- сделал творческое изменение;
- достиг уровня 2;
- посмотрел diff;
- объяснил связь «ввод → условие → метод → результат»;
- предложил следующую функцию;
- практика закончилась до 80-й минуты.

# Если время заканчивается

Сокращать: личного бота → школьный; AI → fallback; prompt → текст кнопки; commit → только diff; дополнительную задачу → убрать.

Не сокращать: запуск, воспроизведение, самостоятельную правку, повторную проверку и рефлексию.
