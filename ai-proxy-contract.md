# HTTP-контракт AI-прокси

Этот контракт изолирован внутри `AiProxyPlanGenerator` и может быть адаптирован после получения финальной спецификации школьного прокси без изменения сценария бота.

## Запрос

`POST` на URL из `LLM_API_URL` с `Content-Type: application/json`.

Если задан `LLM_API_KEY`, добавляется заголовок:

```http
Authorization: Bearer <LLM_API_KEY>
```

Тело:

```json
{
  "model": "optional-model-name",
  "scenario": "STUDY",
  "goal": "Очищенный текст цели",
  "prompt": "Инструкции из plan-generator.ru.json"
}
```

`model` не отправляется, если `LLM_MODEL` пуст. Telegram ID, display name, username, токены и сведения о питомце в тело не попадают.

## Успешный ответ

HTTP 2xx и строго следующий JSON без дополнительных полей:

```json
{
  "summary": "Короткое описание пути",
  "tasks": [
    {"title": "Шаг 1", "description": "Короткое действие"},
    {"title": "Шаг 2", "description": "Короткое действие"},
    {"title": "Шаг 3", "description": "Следующий шаг"}
  ]
}
```

Ограничения:

- ровно три задачи;
- `summary`: 1–300 символов;
- `title`: 1–80 символов;
- `description`: 1–500 символов;
- для `SPORT` запрещаются детерминированно распознаваемые опасные советы;
- XP и уровень игнорируются и не могут задаваться AI.

Timeout, не-2xx ответ, невалидный JSON, дополнительные поля или нарушение ограничений автоматически включают локальный fallback-план. Техническая причина пользователю и в промпт не передаётся.
